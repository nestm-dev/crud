# `@nestm/crud-drizzle`

PostgreSQL-first Drizzle ORM 0.45 adapter for [`@nestm/crud`](../crud). Neutral
CRUD predicates compile to Drizzle SQL expressions, so values remain bound
parameters. Transactions and database-client lifecycle remain under application
control.

The `0.1` alpha is certified for PostgreSQL only.

```sh
pnpm add @nestm/crud @nestm/crud-drizzle drizzle-orm pg
```

```ts
import { bindDrizzleCrud, createDrizzleCrudAdapter } from "@nestm/crud-drizzle";

const usersAdapter = createDrizzleCrudAdapter({
	database: db,
	table: usersTable,
	columns: {
		id: usersTable.id,
		email: usersTable.email,
		createdAt: usersTable.createdAt,
	},
});

const usersBinding = bindDrizzleCrud({
	resource: users,
	fields: ["id", "email", "createdAt"],
	adapter: { useValue: usersAdapter },
	mappings: {
		create: (input) => input,
		update: (input) => input,
		// Maps framework-generated scope/soft-delete values to insert/update keys.
		persistence: (values) => values,
		response: (record, relations) => ({ ...record, ...relations }),
	},
});
```

`columns` maps every CRUD logical field to its Drizzle table column; use
`recordKeys` when a returned row key differs from the logical field.
`mappings.persistence` handles logical values generated by scopes and soft
delete, independently from API create/update mappings.

The binder accepts Nest `useValue`, `useClass`, `useExisting`, and `useFactory`
adapter providers. Use a factory when another Nest module provides the Drizzle
database. The package never creates a driver, opens a pool, or closes a database
connection.

Unique PostgreSQL violations map to `409`, other database constraints to `400`,
and unrecognized failures to a sanitized `500`. The `0.1` alpha is not certified
for non-PostgreSQL Drizzle dialects.
